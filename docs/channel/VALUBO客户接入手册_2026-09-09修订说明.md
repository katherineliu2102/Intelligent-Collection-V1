# VALUBO 客户接入手册修订说明（2026-09-09）

本次主要调整**催收通话结果 API / Callback 定义**：从旧的平铺 `result_label` 改为接通、失败、人/机器、有效沟通、本人和催收收口六层结构。销售业务继续使用旧 `result_label`。

---

## 1. 贵方必须修改的字段

### 1.1 不再读取 `line_outcome.was_ai_connected`

旧版：

```json
{
  "line_outcome": {
    "reason": "NORMAL",
    "was_ringing": true,
    "was_answered": true,
    "was_ai_connected": true
  }
}
```

新版删除 `was_ai_connected`，改为：

```json
{
  "line_outcome": {
    "reason": "NORMAL",
    "was_ringing": true,
    "was_answered": true,
    "party": "human"
  }
}
```

`party` 取值：

- `human`：真人接听；
- `voicemail`：语音信箱；
- `call_screening`：来电筛选助理；
- `null`：未接通。

贵方统计真人接通率时，应使用：

```text
line_outcome.party == "human"
```

`was_answered=true` 只代表线路接通，仍包含信箱和筛选助理，不能直接作为真人接通分子。

### 1.2 催收不再读取 `ai_result.result_label`

旧版催收：

```json
{
  "ai_result": {
    "result_label": "promise_to_pay",
    "summary": "客户承诺还款。",
    "promises": []
  }
}
```

新版催收：

```json
{
  "ai_result": {
    "effective_conversation": true,
    "right_party": "yes",
    "disposition": "promise_to_pay",
    "summary": "The borrower confirmed identity and promised to pay PHP 500 by Friday.",
    "promises": [
      {
        "amount": 500.0,
        "currency": "PHP",
        "promised_date": "2026-09-11",
        "status": "logged"
      }
    ]
  }
}
```

催收新增：

- `effective_conversation`
- `right_party`
- `disposition`

催收删除：

- `result_label`
- `result_label_reasoning`

这是业务定义调整，不是字段改名。旧标签不能机械映射成新版 disposition。

销售域不受影响，仍使用：

```json
{
  "ai_result": {
    "result_label": "interested",
    "summary": "...",
    "promises": []
  }
}
```

### 1.3 未接通新增顶层 `failure_class`

新版未接通结果先按责任层读取：

- `callee`：对方号码或话机结果；
- `network`：线路、运营商或媒体协商；
- `our_system`：我方配置或技术故障。

然后再读取细码：

```json
{
  "failure_class": "callee",
  "final_failure_reason": "INVALID_NUMBER"
}
```

接通成功时两个字段都为 `null`。

---

## 2. 新版六层读取顺序

贵方系统请按以下顺序读取，不要再压成单一标签：

1. 线路是否接通：`line_outcome.was_answered`
2. 未接通原因：`failure_class` + `final_failure_reason`
3. 接通对象：`line_outcome.party`
4. 真人是否形成有效沟通：`ai_result.effective_conversation`
5. 是否本人：`ai_result.right_party`
6. 本人催收收口：`ai_result.disposition`

上一步条件不成立时，后续字段为空。

### 2.1 接通

- `was_answered=true`：真人、信箱和筛选助理都算线路接通。
- `was_answered=false`：未接通。
- `line_outcome.reason=NORMAL` 只表示正常结束，不能据此判断谁先挂断。

### 2.2 有效沟通

仅 `party=human` 时使用：

- `true`：对方至少有一句非空发言；
- `false`：真人接起，但没有形成对方发言；
- `null`：非真人或未接通。

### 2.3 本人判断

- `yes`：借款人本人；
- `no`：第三人；
- `unknown`：无法确认；
- `null`：未进入本人判断。

只有 `right_party=yes` 才会产生 disposition 和付款承诺。

---

## 3. 新版 disposition

七个值互斥：

- `promise_to_pay`：最后形成单笔还款承诺；至少有金额或日期。
- `payment_arrangement`：最后谈妥可描述的分期方案。
- `refused`：认账，但明确拒绝还款或拒绝讨论还款。
- `disputed`：否认债务、金额或合法性，或声称已经支付。
- `hardship`：认账但当前无力偿还，且没有形成方案或承诺。
- `callback`：约定具体回电时间或时间窗口。
- `unresolved`：确认本人并形成沟通，但以上结果都不成立。

以下旧催收标签不再作为新版 API 值：

- `vague_commitment`
- `partial_payment_plan`
- `refused_to_pay`
- `refused_to_discuss`
- `dispute`
- `negotiating`
- `cease_contact`
- `follow_up_required`
- `incomplete`
- `other`
- `NOT_ACCEPT`
- `REJECTED`
- `UNREACHABLE`

贵方数据库和枚举校验应改为接受新版七个 disposition。

---

## 4. 付款承诺边界调整

为避免把案件资料或 Agent 引导误记为用户承诺，新版按以下规则回传：

- 只说 “I will pay”，但没有金额、日期或明确接受的具体方案：`unresolved`，`promises=[]`。
- “I will pay Friday”：日期型 `promise_to_pay`。
- “I will pay everything”：`promise_to_pay`，可用案件逾期额填写金额。
- “If my salary arrives, I will pay Friday”：有日期的条件承诺，按 `promise_to_pay`。
- “I will try to pay Friday”“Maybe”“I should be able to pay Friday”：试探表达，按 `unresolved`。
- Agent 提出金额或日期后，只有对方明确接受才形成承诺；仅回复 `Okay`、考虑、回避或否定，不形成承诺。
- 第三人说借款人会还，不形成 disposition 或 promises。
- 先拒后形成明确承诺，可以是 PTP；先承诺后明确拒绝，最终为 `refused`，旧 promises 清空。
- 最终不是 PTP 或分期时，`promises` 固定为 `[]`。

案件中的逾期金额、历史联系和历史承诺用于通话参考，不会在没有本次对话确认的情况下自动变成本通结果。

## 6. 批次汇总变化

`batch.completed.summary` 仍固定包含：

- `total`
- `completed`
- `failed`

催收批次的其它汇总键改为按当前会话的 `ai_result.disposition` 计数，例如：

```json
{
  "summary": {
    "total": 120,
    "completed": 114,
    "failed": 6,
    "promise_to_pay": 12,
    "callback": 9,
    "unresolved": 21
  }
}
```

销售批次仍按旧 `result_label` 汇总。

## 7. 贵方升级清单

1. 删除对 `line_outcome.was_ai_connected` 的读取。
2. 新增 `line_outcome.party`，用 `party=human` 统计真人接通。
3. 催收删除对 `ai_result.result_label` 的读取。
4. 催收新增 `effective_conversation`、`right_party`、`disposition` 字段。
5. 更新 disposition 枚举为新版七个值。
6. 新增顶层 `failure_class`，失败时先按责任层归类，再读细码。
7. 按新规则处理 `promises`：非 PTP/分期必须为空。
8. 报表分别计算线路接通率、真人接通率、有效沟通率、RPC 率和 PTP 率，并明确各自分母。
9. `batch.completed.summary` 的催收业务键改按 disposition 读取。
10. 保持现有 Callback 验签、幂等和 `2xx` 应答逻辑。
11. 用我方提供的测试批次对拍真人本人、第三人、信箱、筛选助理、未接通和含糊付款表达。

完成上述修改后，再切换到新版催收结果。
