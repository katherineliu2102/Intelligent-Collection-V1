## 1. 抽样标准（与 50 案一致）

| 规则 | 本次做法 |
|------|----------|
| 只抽真实案 | BQ `fintech-all.detail.t_loan_repayment_plan`，无合成 `9900000x` |
| 未结清 | `clear_time IS NULL` 且残值 `amount - paid_amount > 0` |
| DPD | `max(DATE_DIFF(抽样日, due_date))`；已结清期不参与 |
| 关键日 | 抽样日 DPD = **开测日目标 DPD − 1**，使 8/29 落到会改变渠道组合的日子 |
| 一人一案 | 同一 `user_id` 只留一笔 |
| 产品 | 桶内尽量 1 期 / 3 期各半；D91 入催强制三期，已停催强制一期 |
| 金额带 | 桶内打散 low / mid / high（`<2000` / `<8000` / `≥8000`；S0 看 upcoming，逾期看 overdue） |
| 入催窗口 | S0 只抽明日 DPD ≥ −3（`dpd ≤ -4` 数仓不发 `caseEvent`） |

**不做**：不按姓名/电话抽（交付只要 `loan_id`）。进件后若缺联系方式，渠道会空号/fallback，分析时用全量 CSV 的 `loan_id` 对账即可。

## 2. 周末到期日：精确关键日空池与并档

8/28 为周五。还款日几乎不落周末，下列 **精确 today DPD 池为空**：−3、−2、−1、30、60、90。  
若仍强钉这些日，开测日（周六）对应的 D-2 / D-1 / D0 / D+31 / D+61 / D+91 入催 **账面为零**。

并档原则：只抽「开测日仍在同一阶段」的最近有量 DPD，**不**用 `dpd ≤ -4` 的明日仍未入催案。

| 桶 | 原定 8/28 DPD → 8/29 DPD | 实际 8/28 DPD → 8/29 DPD | 对对比的影响 |
|----|--------------------------|---------------------------|--------------|
| S0_D-3 | −4 → −3 | **精确命中** −4 → −3 | 可测 S0 入催 + `S0_REMINDER` |
| S0_D-2 | −3 → −2 | 并入 −4 → **−3** | 与 D-3 同脚本档，**无独立 D-2 样本** |
| S0_D-1 | −2 → −1 | 并入 −4 → **−3** | **测不到** `S0_REMINDER_URGENT` |
| S0_D0 | −1 → 0 | 并入 −4 → **−3** | **测不到 D0 Email** |
| S4_D+31 | 30 → 31 | 31 → **32** | 已进 S4，**错过 D+31 Email 当天** |
| S4_D+61 | 60 → 61 | 61 → **62** | 同 S4 中段，无启用邮件 |
| D91_enter | 90 → 91 | 88 → **89** | 仍为 S4 末，**8/29 尚未停催** |
| 其余桶 | 精确日 | 精确日 | 可按原渠道日对比 |

因此：8/29 本轮 **能对上 50 案渠道日的 Email** 是 **D+1、D+4、D+75**；D0 / D+31 本周末无库存。若要补 D0 / D+31 邮件，需在后续工作日按精确 DPD 加抽，不要和本 200 混成同一「精确日」队列。

## 5. 效果对比时怎么用

1. **主对比键**：`loan_id` + 开测日实际 DPD（以当日 `caseEvent` / `t_ai_collection.dpd` 为准，不要只用桶名）。  
2. **桶名**是「原 50 案设计位」，并档桶的 `tomorrow_dpd` ≠ `intended_tomorrow_dpd`，见全量 CSV。  
3. 与 50 案比渠道效果时：只拿 **精确命中** 的桶（S0_D-3、S1、S2、S3、S4_D+75、S4_D+80、D91_already），S0 其余三档和 S4_D+31 / D91_enter 要单独标注「日历空池」。  
4. 进件前再扫一遍残值；抽样后若当天结清，应从白名单去掉，不必用本说明里的 ID 硬扛。  
5. 白名单请同时配接入 `COLLECTION_PILOT_LOAN_IDS` 与扫描 `COLLECTION_SCAN_CASE_IDS`，避免只进件不扫描或扫到名单外。
